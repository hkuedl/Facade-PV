# Facade-PV

This repository contains the reproducibility code for the paper
“Synergistic Deployment of Rooftop and Facade Photovoltaics Advances
Cost-effective Building Decarbonization in China's Large Cities.”

## Software

- Python 3.10 or later is recommended.
- QGIS 3.36.3 with the [UMEP](https://umep-docs.readthedocs.io/en/latest/index.html)
  plugin is required only to repeat the original solar-radiation simulations.
- A Pyomo-compatible optimization solver is required for
  `Multi_period_planning.py`. The manuscript calculations used Gurobi.
  Configure the solver and its license outside the repository.

Core Python packages include `numpy`, `pandas`, `scipy`,
`scikit-learn`, `scikit-learn-extra`, `pyomo`, `matplotlib`,
`geopandas`, `shapely`, `fiona`, `pyproj`, `xgboost`, and `shap`.
Figure generation additionally uses `frykit`, `geopy`, `openpyxl`, and
`tables` (PyTables).

## Data

The public inputs and prepared outputs are available from
[Baidu Netdisk](https://pan.baidu.com/s/1nz6OqH5hKpRSR72fxIoMdQ?pwd=jx8f)
(access code: `jx8f`).

Download the `##Data` directory into the repository root:

```text
Facade-PV/
├── #Codes/
└── ##Data/
    ├── Evaluation/
    │   ├── UMEP_input/
    │   ├── Sampled_input_output/
    │   ├── Regression_model/
    │   ├── All_input/
    │   └── All_output/
    └── Optimization/
        ├── Electricity_price/
        ├── Loads/
        │   └── Landuse_Loads/
        ├── Other_parameters/
        ├── Fig_input_data/
        └── Planning_results/        # generated by the planning script
```

If the data are stored elsewhere, set `FPV_DATA_ROOT` to the `##Data`
directory. Individual paths can also be overridden with the environment
variables documented at the top of the relevant scripts.

The data folders contain the following inputs and prepared outputs:

- `Evaluation/UMEP_input/`: sampled-city geometry, canopy, wall, and DSM
  inputs used by the QGIS/UMEP solar-radiation simulations.
- `Evaluation/Sampled_input_output/`: sampled-grid features and UMEP-derived
  labels used for model training and validation.
- `Evaluation/Regression_model/`: trained regression models for rooftop and
  facade PV capacity and generation inference.
- `Evaluation/All_input/`: 102-city grid features, city statistics, and
  auxiliary inputs used for nationwide inference and planning.
- `Evaluation/All_output/`: inferred grid-level rooftop/facade PV capacity,
  generation, power profiles, and grid-type arrays. The large
  `Power1.zip`-`Power6.zip` archives are the filtered facade-AOI ML outputs
  used as grid-level inputs by the planning scripts.
- `Optimization/Electricity_price/`: time-of-use tariffs, feed-in prices, and
  carbon-factor workbooks used by the multi-period optimization.
- `Optimization/Loads/`: city load inputs and generated grid-level annual load
  profiles. `Landuse_Loads/` stores the land-use-informed outputs from
  `Load_generate.py`.
- `Optimization/Other_parameters/`: city statistics, north/south heating
  classification, land-use tables, and other planning workbooks.
- `Optimization/Fig_input_data/`: compact figure inputs, including city
  grouping tables, representative-day arrays, the main-case city totals,
  deterministic Fig. 1c/Fig. 3/Fig. 4b caches, and zone-label diagnostics.
- `Optimization/Planning_results/`: prepared Beijing, Wuhan,
  and Shenzhen optimization MAT/JSON files used by Figs. 5-6. Full 102-city
  planning outputs can be regenerated with `Multi_period_planning.py`.

The main planning case uses 35% rooftop availability and 70% of the filtered
facade AOI (42.2% of total facade surface). The planning code scales the
grid-level ML arrays to the saved city totals in
`Optimization/Fig_input_data/main_case_city_totals.csv`.

## Reproduction order

Run commands from the repository root.

1. Optional evaluation/model reproduction:

   ```text
   cd #Codes/Evaluation
   ```

2. Generate the land-use-informed annual loads:

   ```text
   python #Codes/Optimization/Load_generate.py
   ```

3. Run the 2030–2050 planning model. The default processes all 102 cities;
   city-index ranges allow distributed runs:

   ```text
   python #Codes/Optimization/Multi_period_planning.py --city-start 0 --city-end 102
   ```

4. Generate figures:

   ```text
   python #Codes/Figures/Fig_new_1bc.py
   python #Codes/Figures/Fig_new_2.py
   python #Codes/Figures/Fig_new_3.py
   python #Codes/Figures/Fig_new_4.py
   python #Codes/Figures/Fig_new_5.py
   python #Codes/Figures/Fig_new_6.py
   ```

`Fig_new_1bc.py`, `Fig_new_3.py`, and `Fig_new_4.py` use compact
figure caches distributed in `Fig_input_data`. Their raw-result
recalculation paths remain available when all 102 optimization MAT files are
present. `Fig_new_3.py` uses the deterministic `Fig3_*` caches from the main
planning case. Figures 5–6 use the Beijing, Wuhan, and Shenzhen MAT files
distributed in `Planning_results`.

See the subdirectory readme files for file-level details.
